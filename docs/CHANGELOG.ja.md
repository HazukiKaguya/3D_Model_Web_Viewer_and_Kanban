## 3.0.1 — Unity との見た目の整合 · 上流 three-liltoon 0.1.9 · ネイティブ機能への置き換え（2026-10-10 ～ 2026-10-18）

### 3.0.1.1 lilToon スタイルバックエンドの明るさの意味を整合（2026-10-10）

この版はシェーディングのみを変更し、UI と設定形式は変えていません。「lilToon スタイル」バックエンドの**ライティング合成**、
**出力処理**、**基本色の出所**を、比較対象バックエンド（lilToon ソース）の実際の意味に合わせ、目に見える明るさのずれを 2 点修正しました。

#### 修正した問題

| 症状 | 原因 | 対応 |
|---|---|---|
| 既定モデルが**完全な既定設定**で**明るく白っぽい** | スタイル側は「ライトごとの合算」で直接光を自前計算していたが、比較側は**最初の方向ライト**のみを使い、光色を**チャンネルごとに `_LightMinLimit` / `_LightMaxLimit` へクランプ**していた | スタイル側も**1 回の合成**に変更：`A × clamp(メイン + 環境, 下限, 上限) × R`、比較側と同じ意味 |
| 「肌 · アニメーション」プリセット適用後にスタイル側が**逆に暗い** | 基本色の出所が非対称：スタイル側はマテリアルの基本色を**もう一度掛け**、比較側はマテリアル自身の有効色を使っていた | 基本色を「有効設定 → 設定マッピング → vendor 実行既定値」から導出し、同じメインテクスチャ・同じメインレイヤー群で合成 |
| 受光部の広い範囲が**ほぼ純白** | 出力段のトーンマッピング（`LinearToneMapping`、露出 1.15）が比較側には**ない**ため、差がクリップに押し込まれていた | ページのトーンマッピングは維持。直接光を上記の単一合成に変えたところ、広範囲のクリップが消えた |

#### 結果（書き戻し後の実測。黒背景 α 合成、輝度 `L = .2126R + .7152G + .0722B`）

| 状態 | 全画像の平均絶対差 | 輝度差 > 12 の割合 | 主要領域（平均絶対差） |
|---|---|---|---|
| ホーム既定モデル、完全な既定 | 0.029 | 0.076 % | 髪 +0.10 / 顔 +0.37 / 上着 +0.11 / 靴下 +0.01 |
| ホーム既定モデル、「肌 · アニメーション」全体 | 0.000074 | 0.00016 % | 各領域ほぼ 0 |
| Melano（基準ポーズ） | 0.050 | 0.122 % | 顔 −0.14 / 上着 −0.16 |
| Melano、「肌 · アニメーション」全体 | 0.00067 | 0.0029 % | 各領域ほぼ 0 |

- 検収済みの**顔の影の修正**（影法線を無条件に代入、段ごとのバンディングにアンチエイリアス、境界の遷移帯）は**そのまま維持**。
- 「lilToon スタイル」に初めて入るとき、ビューアは**lilToon ブリッジモジュールを 1 回だけ読み込みます**（読み込みのみでレンダラーは切り替えない）。設定マッピングと vendor 実行既定値を得るためです。

#### この版で未検証のこと（正直な記録）

- `_ShadowNormalStrength` の**中間強度**：スライダーは書き込むが、対応するシェーダー分岐はまだ有効でない。
- メインレイヤー 2/3 層（`_UseMain2ndTex` / `_UseMain3rdTex`）の有効化分岐は個別検証していない。
- 顔の影は**輝度**の観点のみ確認し、**形状 / 遷移**の独立検証はしていない。
- 透明背景の分岐、他のモデル、「特定マテリアル」のプリセット対象は未検証。

### 3.0.1.2 上流ランタイムの更新 three-liltoon 0.1.4 → 0.1.9（2026-10-18）

「lilToon ソース」バックエンドが使う上流ランタイムを **0.1.4** から **0.1.9** へ上げました（vendor とマニフェストのみ、自前のシェーディング経路は不変）。

#### 上流がもたらした変化（こちらから見えるもの）

| 項目 | 0.1.4 | 0.1.9 |
|---|---|---|
| 輪郭 | 公開された `shaderVariant` がなく、上流の輪郭を**描けなかった** ✗ | `shaderVariant: 'Hidden/lilToonOutline'` で描ける ✓（実測：スキンメッシュの細い線は正常 ✓） |
| 出力ポリシー | — | 0.1.6 以降、three のトーンマッピング / `outputColorSpace` に追従 ✓（当方は `LinearToneMapping` + 露出 1.15 ✓ 実測で**明るさの移動なし** ✓） |
| レンダーコスト | — | 0.1.9 で重複したマテリアル準備、余分な framebuffer コピーと解決を削減 ✓ |
| テクスチャの向き | — | 文書に明記：マテリアル固有のテクスチャビューは常に `flipY = false` ✓（上流 Issue 3） |

#### 当方の対応

- **輪郭は引き続きすべて自前実装** ✓（混在輪郭スイッチ `HYBRID_UPSTREAM_OUTLINE = false`、`viewer.js` 参照）。
- 理由：BA キャラクターには**モデル固有の輪郭シェルメッシュ**（名前に `_Outline`、例 `CH0155_Milk_Outline`）があり、上流の輪郭を重ねると大きな塊に膨らむ ✗。除外すれば BA 側は正常 ✓ だが、VRC 側は本リポジトリのテストモデルで描画異常（テクスチャ 404、今回の更新とは無関係）⇒ **VRC 側の検証後に有効化**。
- vendor ファイル：`index.js` · `chunk-KNGRDLOZ.js` · `chunk-WFYRXLGW.js` · `gltf.js` · `vrm.js` · `schema/…` · 第三者表記（旧 `chunk-A4BIABDA.js` / `chunk-F6TSGO5L.js` は削除）。
- 配布マニフェスト、5 言語の `DEPLOY` 文書の chunk 表、5 言語の `README` のバージョン番号と輪郭の記述を同期 ✓。

### 3.0.1.3 Unity との見た目の整合（ソースバックエンド）＋上流ネイティブ機能への置き換え（2026-10-18）

この版は「lilToon ソース」バックエンドの**見た目**を Unity に合わせ直し、ソースバックエンドでの自前実装のいくつかを上流 0.1.9 のネイティブ機能へ置き換えました。

#### 修正した問題：ソースバックエンドが明るく、段差が平坦になる

| 症状 | 原因 | 対応 |
|---|---|---|
| 0.1.9 へ上げた後「lilToon ソース」が全体に明るく、影が平坦 | 上流 0.1.6+ が **renderer.toneMapping に従う**ようになり、このページの toon モードは **ACES**。Unity の lilToon マテリアルはトーンマッピングを**しない**（ACES は後処理 Volume からのみ） | ソースバックエンドのマテリアルを `toneMapped = false`（= 0.1.4 の挙動 = Unity の意味）に；**sRGB 出力は維持**（Unity は Linear ⇒ 表示側で sRGB 変換が必要） |

実測（静止シーン、参照状態 = 0.1.4 ビルド）：修正前の正味差 **+0.93 / +0.28 / +0.33**（明るい）→ 修正後 **−0.29 / −0.94 / −1.01**；平均絶対差 **2.20 → 1.34**；>12 の割合 **7.7 % → 3.8 %**。

#### 上流ネイティブ機能へ置き換え

- **輪郭（混在）**：スキンメッシュは `shaderVariant = Hidden/lilToon*Outline` で上流が描画；静的メッシュは自前の逆拡張を継続；上流に任せたメッシュにはシェルを足さない（二重輪郭の回避）。
  ⚠️ **モデル固有の `*_Outline` シェルメッシュは必ず除外**（そうしないと大きな塊に膨らむ、実測済み）；スイッチ `HYBRID_UPSTREAM_OUTLINE`。
- **テクスチャ**：コンストラクタ引数 `textures` を使用（ネイティブな意味；色空間は上流 `LILTOON_TEXTURE_SEMANTICS` が決定）。
- **レンダーキュー**：`enableLilToon(renderer, { materialRenderQueue: true })`（Unity の並び順に近い；実測で画面差なし）。

#### プロパティ表の自己点検

当方の lilToon プロパティ名 **199 個**すべてが、上流の **591 個**のネイティブ名の中に見つかりました（自作・別名 = 0）。

#### 採用しなかったもの（実測してロールバック）

フレーム単位の後処理（トーンマッピングをマテリアルからフレーム pass へ移す、Unity Volume の意味）：上流 `enableLilToon` のレンダーラップと衝突（render target を書き換え、framebuffer を取得する）⇒ 当方の RT が空になる ⇒ **ロールバック**し、マテリアル単位の方式を維持。

#### 既知の残件

- VRC（FBX）側の上流輪郭の見た目は未検証（本リポジトリのテストモデルは真っ黒；0.1.4 でも同様に黒いため fixture の問題）。
- 上流には未マッピングのプロパティが 392 個あります（毛髪 / 屈折 / 宝石 / キューブ反射 など）。

## 3.0.0

> **機能紹介（GitHub Release 3.0.0 と整合）**：この版は「lilToon ソース版の導入 + FBX 体験の改善」を行った大型版です。

1. three.js を **r0.185.1** へ更新；
2. いくつかの問題を修正；
3. レンダーで **Toon** を選んだとき、シェーダー項目に **lilToon ソース**を追加（three-liltoon を導入：上流 lilToon シェーダーコードを直接翻訳）；
4. FBX モデルの読み込み時にプリファブを選んで、パーツの表示・非表示を正しく再現；
5. FBX の閲覧体験を改善し、**anim アニメーション再生（実験的）**を実装；
6. VRC アバターの Unity プロジェクトの `assets` フォルダを丸ごと読み込み可能（中の FBX、プリファブ、テクスチャ、シェーダー設定、シーン、anim を自動認識）；
7. サイトの favicon と 2 ページの `<link rel="icon">`（今回の **3.0.1** で導入、該当節を参照）。

> 以下の本文は同じ版の技術記録です。上の機能紹介と衝突しません：紹介はリリースノート用、本文は実装の追跡用です。

前版（`legacy-v1`）は**ドラッグ可能な 3D キャラクターウィジェット**で、どのサイトにも埋め込める形、シェーディングはゲーム風のトゥーン段差のみでした。

この版はそれを**キャラクター 3D ビューア**にし、主眼は**lilToon スタイルのシェーディングを加え、ビューアの lilToon 設定を Unity の実物と相互運用できるようにする**ことでした。

### 一、lilToon スタイルシェーダーの追加

「シェーダー」ドロップダウンが 2 項目から 3 項目に増えました：

| 選択肢 | 説明 |
|---|---|
| 注入なし（ネイティブ） | モデル固有のマテリアルをそのまま使用、改変なし |
| Cel バンディング | 前版からあるゲーム風トゥーンシェーディング |
| **lilToon スタイル** | 今回追加。lilToon 2.3.4 のソースを参照して実装 |

実装は**lilToon 2.3.4 のソース**に項目ごとに合わせたもので、見た目で合わせたものではありません：

- `Shader/lts.shader` の Properties から**プロパティ 517 個**を基準表として抽出（スクリプト生成・再現可能）、ビューアが既に実装したフィールドと突き合わせ、現在 **228 個**を整合。
- マッピング時に**形状検証**：色↔色、ベクトル↔ベクトル、テクスチャ↔テクスチャ、整数↔整数。形状が合わないものは無理に詰めない。検証済み 80 項目はすべて通過。
- パラメータパネルは lilToon の慣例でグループ化し折りたたみ可能：影の段階、輪郭、Stencil（モデル）、Stencil（輪郭）、MatCap、MatCap 2nd、発光、発光 2nd、ディザ、法線、メインカラー 2nd、メインカラー 3rd、Dissolve。

実装した機能：

- **3 段の影のバンディング**：`_ShadowStrength` / `_ShadowBorder` / `_ShadowBlur`、2・3 層の段階色と境界、`_ShadowBorderRange` の遷移帯。
- **リアルタイム影の受け取り**：層ごとに個別に制御（`_ShadowReceive` など）、式は lilToon と同一（`lerp(1.0, shadow, _ShadowReceive)`）。
- **影の全体スイッチ**：`_UseShadow`。オフなら影の計算ブロックを生成しない。
- **輪郭**：逆拡張輪郭。幅マスク、拡張方向テクスチャ、輪郭の受光、`fixWidthMode`、`skipPattern` など lilToon の輪郭プロパティを含む。
- **メインカラー層**：メインテクスチャの UV 変換・スクロール、HSV 補正、2・3 層のデカールとブレンドモード。
- **リム / MatCap / 逆光 / 反射 / 発光**：lilToon の式と順序で接続。
- **レンダー状態**：`_TransparentMode`、`_Cutoff`、`_Cull` を実際の描画に同期。

### 二、lilToon `.asset` プリセットとの双方向互換

目的は**ビューアの設定と Unity の lilToon 実出力ファイルが互いに読み書きできる**ようにすること。両方向とも実装しました：

- **読み込み**：`.asset`（Unity の lilToon プリセット）、`.mat`（マテリアル）、`.json` を認識。ドロップすると種類を自動判定。
- **書き出し**：Unity がそのまま読み込める lilToon プリセットテキストを生成。フィールド名は lilToon の元の名前（`_UseOutline` など）、値は float32。

付随する詳細：

- **公式プリセット 19 個を内蔵**。lilToon 同梱の `Presets/*.asset` から直接生成（手写しではない）。分類（肌、髪、布、自然、無機物、効果、その他）は Unity 側と一致。
- **マテリアル単位の設定**：パネル上部のマテリアルドロップダウンで、特定のマテリアルにだけプリセットを適用したりパラメータを変えたりでき、他は全体既定のまま。変更したマテリアルには印が付き、上書きを一括で消せる。
- **書き出しは lilToon パラメータパネル内**にあり、Unity の慣例と同じ（プリセットの読み書きは lilToon 自身のメニューにある）。書き出し時に選択可能：

  - **種類**：既定「自動」、マテリアル名から推定（hair→髪、skin→肌、cloth→布、その他→その他）；7 項目のいずれかを手動指定も可。
  - **シェーダー**：既定「自動」、現在のパラメータから導出；具体的なバリアントを手動指定も可。
  - **現在のマテリアルを書き出し**：1 マテリアル 1 `.asset`、ファイル名は `モデル名_マテリアル名.asset`。
  - **すべてのマテリアルを書き出し**：マテリアルごとに 1 ファイル。

### 三、サブシェーダー（バリアント）の扱い

これは今回の相互運用で得た重要な発見なので、独立した節にします。

**Unity の lilToon の「メインシェーダー」はすべての機能を含んでいません。**
メインシェーダー `lilToon`（`lts.shader`）には pass が 4 つしかなく（`FORWARD`、`FORWARD_ADD`、`SHADOW_CASTER`、`META`）、**輪郭の pass がありません**。
したがってメインシェーダーのままでは `_UseOutline = 1` でも輪郭は描画されず、`Hidden/lilToonOutline`（`FORWARD_OUTLINE` などが増える）へ切り替える必要があります。

また lilToon にはシェーダーが **64 個**あり、**マテリアルパネルで選べる名前は 1 個だけ**。残り 63 個は `Hidden/*` または `_lil/*` のバリアント（ガラス屈折、透明、毛髪、宝石など）で、**プリセット経由でしか結び付けられません**。

そこでビューアは書き出し時に正しいサブシェーダーを導出して書き込みます：

```
_TransparentMode で基本モードを決定
  ├ 輪郭がオンのときは対応する *Outline バリアントへ
  ├ そのモードに輪郭バリアントがない（屈折 / 毛髪 / 宝石）ときは輪郭なしへ
  └ パラメータで決められない（屈折、透明）ときはプリセット自身の情報を使う
```

書き出し画面には今回どのバリアントを結び付けるかを表示します。例：
「サブシェーダー → Hidden/lilToonOutline（Opaque + 輪郭）」。

### 四、ビューア自体の変化

前版のウィジェットに比べ、インターフェースを全面的に置き換えました：

- **フローティングウィンドウ**：各パネルはドラッグ・最小化・ドッキング可能な独立ウィンドウ。
- **パネル**：シェーディングと輪郭、lilToon パラメータ、パーツ、シーン、書き出し。
- **ライティングプリセット**：昼、朝 / 夕方、夜。さらにメインライトの方位角・仰角・強さ・色、環境の天井色・地面色の微調整。
- **レンダーモード**：オリジナル PBR、トゥーン Cel。輪郭はオン/オフと太さ調整。
- **パーツパネル**：任意パーツと小道具の非表示（ボーンスケールによる非表示を含む）、ロックと分離表示に対応。
- **シーン補助表示**：グリッド床、座標軸など。既定はすべてオフで、メインページが明示的にオンにする。
- **カメラ**：上面・下面・軸ビュー、既定は正面ビュー、720° 無段回転。
- **モデル位置補正**：回転基準とモデルオフセットを設定でき、「キャラクターが画面から出る」を解決。
- **FBX 対応**：前版は glTF のみ。この版は FBX に対応し、FBX にありがちな絶対パスのテクスチャも処理（ファイル名で照合、`textureBase` / `textureMap` のフォールバック）。
- **設定駆動**：パラメータ全体が JSON（`assets/sample.json` が基準）。URL パラメータ、同名設定の自動読み込み、現在設定の書き出しに対応。
- **埋め込み**：自己完結の単一ファイル版（importmap 不要）。`data-ba3d-*` 属性で渡すか、JS API を直接呼ぶ。
- **口の修正**：前版の方式を踏襲（UV アイランド分割 + 口のアトラス + `bone_mouth` 駆動）。マテリアルはレンダーモードに追従するようになりました。

プロジェクト側も変わりました：

- `src/` モジュール + `dist/` ウィジェットから、`viewer.js` + `index.html` + `assets/` へ。自己完結の単一ファイル版も別途提供。
- **生成器と検査器**を追加：lilToon のプロパティ表、フィールド対応表、プリセット、シェーダー表はすべて lilToon ソースからスクリプトで生成し、`--check` モードを持つ。他に一貫性検査器と固定の配布マニフェスト。

### 五、修正した問題

- **カリング方向が逆**：Unity の `Cull Back` は「裏面をカリング」（表面だけ描く）の意味ですが、「裏面だけ描く」と解釈していたため、プリセット適用後にモデルが裏返って白く見えました。
- **カットオフのしきい値の誤用**：`_Cutoff` は Cutout モードでのみ有効ですが、「設定に cutoff があれば適用」としていたため、`_Cutoff` の既定値 0.5 により既存の alphaTest が 0.5 に強制され、半透明のピクセルが切り取られてマテリアルが透明に見えました。現在は Cutout モードのときだけ使用します。
- **影の全体スイッチが未接続**：`_UseShadow` がまったくマッピングされておらず、公式プリセット 19 個のうち 5 個（肌·フラット、肌·輪郭、金属 MatCap、ガラス、軽いガラス）が明示的に影を切っているのに、プリセット適用後も影が残っていました。
- **派生スイッチの自己整合**：`_UseRim` / `_UseMatCap` / `_UseOutline` のように下位パラメータから導出されるスイッチが、書き出し自己点検で偽の「未認識フィールド」を出さなくなり、設定とプリセットの間の往復書き込みも互いを上書きしなくなりました。

### 六、既知の制限

- lilToon の 517 プロパティのうち 228 個をマッピングしています。残りには**見た目に直接影響するが未実装**のフィールドがあり、影の段階、発光、反射、MatCap、リム、逆光、Dissolve などのグループに存在します。これらは現在プレビューにも影響せず、書き出しもされません。不足の全リストは `LILTOON2.x.md` と `CONFIG.md` の「未完了」節にあります。
- **`.mat` マテリアルファイルの書き出しは未実装**（読み込みのみ）。Unity のマテリアルは読み込めますが、`.mat` の生成はまだ空です。
- 屈折、毛髪、宝石の 3 モードは Web 側に対応するシェーダー実装がなく、プレビューでは透明として扱い注意を表示します。書き出し時は正しいサブシェーダーを記録します。
- 複数インスタンスはそれぞれレンダラーと GPU リソースを持ちます（前版からの制限を継承）。複数のキャラクターが必要な場合は 1 インスタンスで切り替えることを勧めます。

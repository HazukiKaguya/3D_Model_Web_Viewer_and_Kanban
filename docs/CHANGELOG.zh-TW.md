### 3.0.1.1 lilToon 風格後端的亮度語義對齊（2026-10-10）

這一版只動著色，不改界面與設定格式：把「lilToon 風格」後端的**光照合成**、
**輸出處理**與**基础色來源**，按對照後端（lilToon 源碼）的實際語義對齊，
修掉兩處肉眼可見的亮度偏差。

#### 修的問題

| 现象 | 原因 | 處理 |
|---|---|---|
| 預設模型在**纯預設設定**下**偏亮、發白** | 風格端按「逐灯求和」自己算直接光，而對照端只取**首盏方向光**、並把光色**逐通道夾到 `_LightMinLimit` / `_LightMaxLimit`** | 風格端改成**一次合成**：`A × clamp(主光 + 環境, 下限, 上限) × R`，與對照端同語義 |
| 套「皮膚 · 動畫」預設後風格端**反而偏暗** | 基础色來源不對稱：風格端把材質基础色**又乘了一遍**，對照端吃的是材質自身的有效色 | 基础色改由「有效設定 → 設定映射 → vendor 運行預設」推導，與同一張主貼圖、同一套主色層一起合成 |
| 受光区大面積**接近纯白** | 輸出環節的色調映射（`LinearToneMapping`，曝光 1.15）對照端**沒有**，這部分差異被壓成裁切 | 保留頁面色調映射；直接光改成上面的單一合成後，大面積裁切消失 |

#### 結果（寫回後實測；黑底 α 合成，亮度 `L = .2126R + .7152G + .0722B`）

| 状態 | 全圖平均绝對差 | 亮度差 > 12 占比 | 關鍵区域（平均绝對差） |
|---|---|---|---|
| 首頁預設模型，纯預設 | 0.029 | 0.076 % | 頭發 +0.10 / 臉 +0.37 / 外套 +0.11 / 襪 +0.01 |
| 首頁預設模型，「皮膚 · 動畫」全局 | 0.000074 | 0.00016 % | 各区域約 0 |
| Melano（基準姿態） | 0.050 | 0.122 % | 臉 −0.14 / 外套 −0.16 |
| Melano，「皮膚 · 動畫」全局 | 0.00067 | 0.0029 % | 各区域約 0 |

- 已驗收的**臉部陰影修復**（陰影法線無條件賦值、逐層分檔含抗鋸齒、邊界過渡帶）**保持不動**。
- 首次進入「lilToon 風格」時，查看器會**順帶裝載一次 lilToon 橋接模塊**（只加載模塊，
  不切換渲染後端），用於取設定映射與 vendor 運行預設值。

#### 本版尚未驗證（誠實記錄）

- `_ShadowNormalStrength` 的**中間強度**：滑塊可以寫、對應的著色器分支尚未生效。
- 主色層第二/第三層（`_UseMain2ndTex` / `_UseMain3rdTex`）的啟用分支未單独驗證。
- 臉部陰影目前只核了**亮度**口徑，**形状 / 過渡**的独立核對未做。
- 透明背景分支、其它模型與「指定材質」的預設目標未測。

### 3.0.1.3 觀感對齊 Unity（源碼後端）+ 上游原生能力替換（2026-10-18）

這一版把「lilToon 源碼」後端的**觀感**重新對齊到 Unity，並把我們在源碼後端上的幾處自實现換成上游 0.1.9 的原生能力。

#### 修的問題：源碼後端變亮 / 分檔變平

| 现象 | 原因 | 處理 |
|---|---|---|
| 升到 0.1.9 後「lilToon 源碼」整體偏亮、陰影變平 | 上游 0.1.6+ 開始**遵循 renderer.toneMapping**，而本頁面 toon 模式是 **ACES**；Unity 的 lilToon 材質**不做** tone mapping（ACES 只可能來自後處理 Volume） | 源碼後端材質 `toneMapped = false`（= 0.1.4 行為 = Unity 語義）；**sRGB 輸出保留**（Unity 是 Linear ⇒ 顯示端本來就要做 sRGB） |

實測（靜止場景；參考態 = 0.1.4 構建）：修前淨差 **+0.93 / +0.28 / +0.33**（偏亮）→ 修後 **−0.29 / −0.94 / −1.01**；平均绝對差 **2.20 → 1.34**；>12 占比 **7.7% → 3.8%**。

#### 換成上游原生能力

- **描邊（混合）**：蒙皮網格改用 `shaderVariant = Hidden/lilToon*Outline` 由上游绘制；靜態網格繼續用自研反殼；交给上游的網格不再加殼（避免雙描邊）。
  ⚠️ **模型自帶的 `*_Outline` 殼網格必須排除**（否則會膨脹成大片實體，已實測）；開關 `HYBRID_UPSTREAM_OUTLINE`。
- **貼圖**：改用構造參數 `textures`（原生語義；色彩空間由上游 `LILTOON_TEXTURE_SEMANTICS` 決定）。
- **渲染隊列**：`enableLilToon(renderer, { materialRenderQueue: true })`（更接近 Unity 的排序語義；實測對画面無影響）。

#### 屬性錶自檢

我們的 **199** 個 lilToon 屬性名**全部**能在上游 **591** 個原生名裡找到（自造/別名 = 0）。

#### 未采用（已實測並回退）

幀級後處理（把 tone mapping 從材質移到整幀 pass，Unity Volume 語義）：與上游 `enableLilToon` 的渲染包裝衝突（它會改寫 render target / 做 framebuffer 捕獲）⇒ 我們的 RT 為空 ⇒ **回退**，維持材質級方案。

#### 已知遺留

- VRC（FBX）側的上游描邊觀感未驗（本倉庫測試模型全黑；0.1.4 同樣黑，屬 fixture 問題）。
- 上游另有 392 個屬性未映射（毛發 / 折射 / 寶石 / 立方體反射等）。

### 一、新增 lilToon 風格著色器

「著色器」下拉從原來的兩檔變成三檔：

| 選項 | 說明 |
|---|---|
| 不注入（原生） | 用模型自帶的材質，不做任何改造 |
| Cel 分檔 | 上一版就有的游戲觀感卡通著色 |
| **lilToon 風格** | 本次新增，參照 lilToon 2.3.4 源碼實现 |

實现方式是照著 **lilToon 2.3.4 的源碼**逐項對齊，不是憑觀感調參：

- 從 `Shader/lts.shader` 的 Properties 段落提取出 **517 個屬性**作為基準錶
  （腳本生成，可復现），再和查看器已經實现的字段逐一對應，目前對齊 **228 個**。
- 映射時做**形状校驗**：顏色對顏色、向量對向量、貼圖對貼圖、整數對整數，
  形状不一致的一律不硬塞。已核對過的 80 項形状全部通過。
- 參數面板按 lilToon 的習慣分組，可折疊：陰影分檔、描邊 Outline、Stencil 模型、
  Stencil 描邊、MatCap、MatCap 2nd、自發光、自發光 2nd、抖動 Dither、
  法線 Normal、主色層 2nd、主色層 3rd、Dissolve。

具體實现的功能：

- **三層陰影分檔**：`_ShadowStrength` / `_ShadowBorder` / `_ShadowBlur`，
  以及第二、第三層的分檔顏色與邊界，還有 `_ShadowBorderRange` 的過渡帶。
- **實時陰影接收**：每層可單独決定是否接收投影（`_ShadowReceive` 等），
  公式與 lilToon 一致（`lerp(1.0, shadow, _ShadowReceive)`）。
- **陰影總開關**：`_UseShadow`，關掉時整段陰影計算不生成。
- **描邊**：反殼描邊，含寬度遮罩、外擴方向貼圖、描邊受光、`fixWidthMode`、
  `skipPattern` 等 lilToon 的描邊屬性。
- **主色層**：主色貼圖的 UV 變換與滾動、HSV 校正、第二/第三層的貼花與混合模式。
- **邊緣光 / MatCap / 背光 / 反射 / 發光**：按 lilToon 的公式與順序接入。
- **渲染状態**：`_TransparentMode`、`_Cutoff`、`_Cull` 同步到實際渲染。

### 二、lilToon `.asset` 預設的雙向兼容

目標是**讓查看器的設定和 Unity 裡 lilToon 實際產出的檔案能互相讀寫**，
兩個方向都做了：

- **導入**：認 `.asset`（Unity 的 lilToon 預設）、`.mat`（材質）、`.json`，
  拖進來自動判斷類型。
- **匯出**：生成 Unity 能直接加載的 lilToon 預設文本，字段名用 lilToon 的原名
  （`_UseOutline` 這類），數值按 float32 寫入。

配套細節：

- **內置 19 個官方預設**，直接從 lilToon 自帶的 `Presets/*.asset` 生成，
  不是手抄的。分類（皮膚、頭發、布料、自然、無機物、效果、其他）與 Unity 側一致。
- **逐材質設定**：面板頂部有材質下拉，可以只给某個材質套預設或改參數，
  其餘材質保持全局預設；改過的材質在下拉裡帶標記，也能一鍵清除覆盖。
- **匯出入口放在 lilToon 參數面板裡**，和 Unity 的習慣一致（預設的導入匯出都在
  lilToon 自己的選單裡）。匯出時可以選：

  - **類型**：預設「自動」，按材質名猜（hair 判成頭發、skin 判成皮膚、
    cloth 判成布料，其餘歸到其他）；也可以手動指定七項之一。
  - **著色器**：預設「自動」，按當前參數推導；也可以手動指定具體變體。
  - **匯出當前材質**：一個材質一個 `.asset`，檔案名是 `模型名_材質名.asset`。
  - **匯出全部材質**：每個材質各出一個檔案。

### 三、子著色器（變體）的處理

這是本次互通工作的關鍵發现，單独說明。

**Unity 裡 lilToon 的「主著色器」並不包含全部功能。**
主著色器 `lilToon`（`lts.shader`）只掛了 4 個 pass
（`FORWARD`、`FORWARD_ADD`、`SHADOW_CASTER`、`META`），**沒有描邊 pass**。
所以材質用主著色器時，即使 `_UseOutline = 1`，描邊也不會渲染；
必須換成 `Hidden/lilToonOutline`（它多出 `FORWARD_OUTLINE` 等 pass）。

而 lilToon 一共 **64 個著色器**，其中**只有 1 個是能在材質面板裡選到的可見名**，
其餘 63 個都是 `Hidden/*` 或 `_lil/*` 變體（玻璃折射、透明、毛發、寶石等），
**只能靠預設去绑定**。

所以查看器匯出預設時會自動推導並寫入正確的子著色器：

```
按 _TransparentMode 定基础模式
  ├ 描邊開啟時換成對應的 *Outline 變體
  ├ 該模式沒有描邊變體（折射 / 毛發 / 寶石）就退回不帶描邊的
  └ 參數推不出來的（折射、透明）用預設本身攜帶的資訊
```

匯出界面上會顯示這次會绑定哪個變體，例如
「子著色器 → Hidden/lilToonOutline（Opaque + 描邊）」。

### 四、查看器本身的變化

相對上一版的看板掛件，形態上換了一整套界面：

- **部件面板**：隱藏可選部件與道具（含按骨骼縮放隱藏道具），支持鎖定與隔離查看。
- **場景輔助顯示**：網格地面、坐標軸等，預設全關，主頁面顯式打開。
- **相機**：頂視圖、底視圖、軸視圖、預設正面視圖，720° 無極旋轉。
- **模型位置修正**：旋轉基準與模型偏移都可設定，解決「角色跑出画面」。
- **FBX 支持**：上一版只吃 glTF；這一版支持 FBX，並處理 FBX 裡常見的绝對路徑貼圖
  （按檔案名匹配、给 `textureBase` / `textureMap` 兜底）。
- **設定化**：整套參數走 JSON（`assets/sample.json` 是基線），支持 URL 參數傳入、
  自動加載同名設定、以及匯出當前設定。
- **嵌入方式**：自包含單檔案版（不需要 importmap），用 `data-ba3d-*` 屬性傳參，
  也可以直接調 JS API。
- **嘴部修復**：沿用上一版的方案（拆 UV 岛 + 嘴部圖集 + `bone_mouth` 驅動），

- 由 `src/` 分模塊 + `dist/` 掛件，改為 `viewer.js` + `index.html` + `assets/`，
  另出一份自包含單檔案版。
- 增加了**生成器與檢查器**：lilToon 屬性錶、字段映射錶、預設、著色器錶都由腳本
  從 lilToon 源碼生成，帶 `--check` 模式；另有若乾一致性檢查器與固定的部署清單。

### 五、修復的問題

- **剔除方向反了**：Unity 的 `Cull Back` 意思是「剔除背面」（只画正面），
  之前理解成了「只画背面」，導致套上預設後模型裡外翻轉、看起來發白。
- **裁剪閾值被誤用**：`_Cutoff` 只在 Cutout 模式生效，之前寫成了「只要設定裡有
  cutoff 就套用」，而 `_Cutoff` 的預設值本來就是 0.5，於是材質原有的 alphaTest
  被強行改成 0.5，半透明像素被裁掉，錶现為材質變透明。现在只有明確是 Cutout
  模式才使用它。
- **陰影總開關沒接**：`_UseShadow` 之前完全沒有映射，19 個官方預設裡有 5 個
  （皮膚·平塗、皮膚·描邊、金屬 MatCap、玻璃、輕玻璃）明確關掉了陰影，
  這些「關陰影」的意圖收不到，套完預設陰影還在。
- **派生開關的自洽**：`_UseRim` / `_UseMatCap` / `_UseOutline` 這類由子參數推導的
  開關，匯出自檢時不再產生假的「未識別字段」；設定與預設之間來回寫也不再互相覆盖。

### 六、已知限制

- lilToon 的 517 個屬性裡我們映射了 228 個，其餘當中還有一批**會直接影響外觀、
  但尚未實现**的字段，陰影分檔、發光、反射、MatCap、邊緣光、背光、溶解等分組裡
  都有。這些字段目前既不影響預覽，也不會被匯出。完整缺口清單見 `LILTOON2.x.md`
  與 `CONFIG.md` 的「未完成」一節。
- **`.mat` 材質檔案的匯出還沒做**（只支持導入）。可以把 Unity 的材質導進來，
  但反過來生成 `.mat` 還是空白。
- 折射、毛發、寶石三種模式在網頁端沒有對應的著色器實现，預覽時會按透明處理並
  给出提示；匯出時仍會寫入正確的子著色器。
- 多個實例會各自持有一份渲染器與 GPU 資源（沿用上一版的限制），
  需要多個小人時建議只用一個實例切換。

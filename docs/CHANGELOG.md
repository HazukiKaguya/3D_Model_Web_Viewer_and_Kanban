### 3.0.1.1 lilToon 风格后端的亮度语义对齐（2026-10-10）

这一版只动着色，不改界面与配置格式：把「lilToon 风格」后端的**光照合成**、
**输出处理**与**基础色来源**，按对照后端（lilToon 源码）的实际语义对齐，
修掉两处肉眼可见的亮度偏差。

#### 修的问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 默认模型在**纯默认配置**下**偏亮、发白** | 风格端按「逐灯求和」自己算直接光，而对照端只取**首盏方向光**、并把光色**逐通道夹到 `_LightMinLimit` / `_LightMaxLimit`** | 风格端改成**一次合成**：`A × clamp(主光 + 环境, 下限, 上限) × R`，与对照端同语义 |
| 套「皮肤 · 动画」预设后风格端**反而偏暗** | 基础色来源不对称：风格端把材质基础色**又乘了一遍**，对照端吃的是材质自身的有效色 | 基础色改由「有效配置 → 配置映射 → vendor 运行默认」推导，与同一张主贴图、同一套主色层一起合成 |
| 受光区大面积**接近纯白** | 输出环节的色调映射（`LinearToneMapping`，曝光 1.15）对照端**没有**，这部分差异被压成裁切 | 保留页面色调映射；直接光改成上面的单一合成后，大面积裁切消失 |

#### 结果（写回后实测；黑底 α 合成，亮度 `L = .2126R + .7152G + .0722B`）

| 状态 | 全图平均绝对差 | 亮度差 > 12 占比 | 关键区域（平均绝对差） |
|---|---|---|---|
| 首页默认模型，纯默认 | 0.029 | 0.076 % | 头发 +0.10 / 脸 +0.37 / 外套 +0.11 / 袜 +0.01 |
| 首页默认模型，「皮肤 · 动画」全局 | 0.000074 | 0.00016 % | 各区域约 0 |
| Melano（基准姿态） | 0.050 | 0.122 % | 脸 −0.14 / 外套 −0.16 |
| Melano，「皮肤 · 动画」全局 | 0.00067 | 0.0029 % | 各区域约 0 |

- 已验收的**脸部阴影修复**（阴影法线无条件赋值、逐层分档含抗锯齿、边界过渡带）**保持不动**。
- 首次进入「lilToon 风格」时，查看器会**顺带装载一次 lilToon 桥接模块**（只加载模块，
  不切换渲染后端），用于取配置映射与 vendor 运行默认值。

#### 本版尚未验证（诚实记录）

- `_ShadowNormalStrength` 的**中间强度**：滑块可以写、对应的着色器分支尚未生效。
- 主色层第二/第三层（`_UseMain2ndTex` / `_UseMain3rdTex`）的启用分支未单独验证。
- 脸部阴影目前只核了**亮度**口径，**形状 / 过渡**的独立核对未做。
- 透明背景分支、其它模型与「指定材质」的预设目标未测。

### 3.0.1.2 上游运行时升级 three-liltoon 0.1.4 → 0.1.9（2026-10-18）

「lilToon 源码」后端用的上游运行时从 **0.1.4** 升到 **0.1.9**（只换 vendor 与清单，不动我们自己的着色路径）。

#### 上游带来的变化（我们这边可见的）

| 项 | 0.1.4 | 0.1.9 |
|---|---|---|
| 描边 | 没有公开的 `shaderVariant` ⇒ 上游描边**画不出来** ✗ | `shaderVariant: 'Hidden/lilToonOutline'` 能画 ✓（实测：蒙皮网格细边正常 ✓） |
| 输出策略 | — | 0.1.6 起跟随 three 的色调映射 / `outputColorSpace` ✓（我们用 `LinearToneMapping` + 曝光 1.15 ✓ 实测**无亮度位移** ✓） |
| 渲染开销 | — | 0.1.9 减少重复材质准备、多余 framebuffer 拷贝与解析 ✓ |
| 贴图方向 | — | 文档写明：材质自带的贴图视图一律 `flipY = false` ✓（上游 Issue 3） |

#### 我们的处置

- **描边仍全部走自研实现** ✓（混合描边开关 `HYBRID_UPSTREAM_OUTLINE = false`，见 `viewer.js`）。
- 原因：BA 小人里**模型自带的描边壳网格**（名字带 `_Outline`，如 `CH0155_Milk_Outline`）套上游描边会膨胀成大片实体 ✗；把它排除后 BA 侧已验证正常 ✓，但 VRC 侧在本仓库的测试模型上渲染异常（缺贴图 404，与本次升级无关）⇒ **等 VRC 侧验证后再开**。
- vendor 文件：`index.js` · `chunk-KNGRDLOZ.js` · `chunk-WFYRXLGW.js` · `gltf.js` · `vrm.js` · `schema/…` · 第三方声明（旧名 `chunk-A4BIABDA.js` / `chunk-F6TSGO5L.js` 已移除）。
- 部署清单、五语 `DEPLOY` 文档的 chunk 表、五语 `README` 的版本号与描边表述已同步 ✓。

### 3.0.1.3 观感对齐 Unity（源码后端）+ 上游原生能力替换（2026-10-18）

这一版把「lilToon 源码」后端的**观感**重新对齐到 Unity，并把我们在源码后端上的几处自实现换成上游 0.1.9 的原生能力。

#### 修的问题：源码后端变亮 / 分档变平

| 现象 | 原因 | 处理 |
|---|---|---|
| 升到 0.1.9 后「lilToon 源码」整体偏亮、阴影变平 | 上游 0.1.6+ 开始**遵循 renderer.toneMapping**，而本页面 toon 模式是 **ACES**；Unity 的 lilToon 材质**不做** tone mapping（ACES 只可能来自后处理 Volume） | 源码后端材质 `toneMapped = false`（= 0.1.4 行为 = Unity 语义）；**sRGB 输出保留**（Unity 是 Linear ⇒ 显示端本来就要做 sRGB） |

实测（静止场景；参考态 = 0.1.4 构建）：修前净差 **+0.93 / +0.28 / +0.33**（偏亮）→ 修后 **−0.29 / −0.94 / −1.01**；平均绝对差 **2.20 → 1.34**；>12 占比 **7.7% → 3.8%**。

#### 换成上游原生能力

- **描边（混合）**：蒙皮网格改用 `shaderVariant = Hidden/lilToon*Outline` 由上游绘制；静态网格继续用自研反壳；交给上游的网格不再加壳（避免双描边）。
  ⚠️ **模型自带的 `*_Outline` 壳网格必须排除**（否则会膨胀成大片实体，已实测）；开关 `HYBRID_UPSTREAM_OUTLINE`。
- **贴图**：改用构造参数 `textures`（原生语义；色彩空间由上游 `LILTOON_TEXTURE_SEMANTICS` 决定）。
- **渲染队列**：`enableLilToon(renderer, { materialRenderQueue: true })`（更接近 Unity 的排序语义；实测对画面无影响）。

#### 属性表自检

我们的 **199** 个 lilToon 属性名**全部**能在上游 **591** 个原生名里找到（自造/别名 = 0）。

#### 未采用（已实测并回退）

帧级后处理（把 tone mapping 从材质移到整帧 pass，Unity Volume 语义）：与上游 `enableLilToon` 的渲染包装冲突（它会改写 render target / 做 framebuffer 捕获）⇒ 我们的 RT 为空 ⇒ **回退**，维持材质级方案。

#### 已知遗留

- VRC（FBX）侧的上游描边观感未验（本仓库测试模型全黑；0.1.4 同样黑，属 fixture 问题）。
- 上游另有 392 个属性未映射（毛发 / 折射 / 宝石 / 立方体反射等）。

上一版（`legacy-v1`）的定位是**可拖拽的 3D 小人看板挂件**：一个能嵌进任意网站的

### 一、新增 lilToon 风格着色器

「着色器」下拉从原来的两档变成三档：

| 选项 | 说明 |
|---|---|
| 不注入（原生） | 用模型自带的材质，不做任何改造 |
| Cel 分档 | 上一版就有的游戏观感卡通着色 |
| **lilToon 风格** | 本次新增，参照 lilToon 2.3.4 源码实现 |

实现方式是照着 **lilToon 2.3.4 的源码**逐项对齐，不是凭观感调参：

- 从 `Shader/lts.shader` 的 Properties 段落提取出 **517 个属性**作为基准表
  （脚本生成，可复现），再和查看器已经实现的字段逐一对应，目前对齐 **228 个**。
- 映射时做**形状校验**：颜色对颜色、向量对向量、贴图对贴图、整数对整数，
  形状不一致的一律不硬塞。已核对过的 80 项形状全部通过。
- 参数面板按 lilToon 的习惯分组，可折叠：阴影分档、描边 Outline、Stencil 模型、
  Stencil 描边、MatCap、MatCap 2nd、自发光、自发光 2nd、抖动 Dither、
  法线 Normal、主色层 2nd、主色层 3rd、Dissolve。

具体实现的功能：

- **三层阴影分档**：`_ShadowStrength` / `_ShadowBorder` / `_ShadowBlur`，
  以及第二、第三层的分档颜色与边界，还有 `_ShadowBorderRange` 的过渡带。
- **实时阴影接收**：每层可单独决定是否接收投影（`_ShadowReceive` 等），
  公式与 lilToon 一致（`lerp(1.0, shadow, _ShadowReceive)`）。
- **阴影总开关**：`_UseShadow`，关掉时整段阴影计算不生成。
- **描边**：反壳描边，含宽度遮罩、外扩方向贴图、描边受光、`fixWidthMode`、
  `skipPattern` 等 lilToon 的描边属性。
- **主色层**：主色贴图的 UV 变换与滚动、HSV 校正、第二/第三层的贴花与混合模式。
- **边缘光 / MatCap / 背光 / 反射 / 发光**：按 lilToon 的公式与顺序接入。
- **渲染状态**：`_TransparentMode`、`_Cutoff`、`_Cull` 同步到实际渲染。

### 二、lilToon `.asset` 预设的双向兼容

目标是**让查看器的配置和 Unity 里 lilToon 实际产出的文件能互相读写**，
两个方向都做了：

- **导入**：认 `.asset`（Unity 的 lilToon 预设）、`.mat`（材质）、`.json`，
  拖进来自动判断类型。
- **导出**：生成 Unity 能直接加载的 lilToon 预设文本，字段名用 lilToon 的原名
  （`_UseOutline` 这类），数值按 float32 写入。

配套细节：

- **内置 19 个官方预设**，直接从 lilToon 自带的 `Presets/*.asset` 生成，
  不是手抄的。分类（皮肤、头发、布料、自然、无机物、效果、其他）与 Unity 侧一致。
- **逐材质配置**：面板顶部有材质下拉，可以只给某个材质套预设或改参数，
  其余材质保持全局默认；改过的材质在下拉里带标记，也能一键清除覆盖。
- **导出入口放在 lilToon 参数面板里**，和 Unity 的习惯一致（预设的导入导出都在
  lilToon 自己的选单里）。导出时可以选：

  - **类型**：默认「自动」，按材质名猜（hair 判成头发、skin 判成皮肤、
    cloth 判成布料，其余归到其他）；也可以手动指定七项之一。
  - **着色器**：默认「自动」，按当前参数推导；也可以手动指定具体变体。
  - **导出当前材质**：一个材质一个 `.asset`，文件名是 `模型名_材质名.asset`。
  - **导出全部材质**：每个材质各出一个文件。

### 三、子着色器（变体）的处理

这是本次互通工作的关键发现，单独说明。

**Unity 里 lilToon 的「主着色器」并不包含全部功能。**
主着色器 `lilToon`（`lts.shader`）只挂了 4 个 pass
（`FORWARD`、`FORWARD_ADD`、`SHADOW_CASTER`、`META`），**没有描边 pass**。
所以材质用主着色器时，即使 `_UseOutline = 1`，描边也不会渲染；
必须换成 `Hidden/lilToonOutline`（它多出 `FORWARD_OUTLINE` 等 pass）。

而 lilToon 一共 **64 个着色器**，其中**只有 1 个是能在材质面板里选到的可见名**，
其余 63 个都是 `Hidden/*` 或 `_lil/*` 变体（玻璃折射、透明、毛发、宝石等），
**只能靠预设去绑定**。

所以查看器导出预设时会自动推导并写入正确的子着色器：

```
按 _TransparentMode 定基础模式
  ├ 描边开启时换成对应的 *Outline 变体
  ├ 该模式没有描边变体（折射 / 毛发 / 宝石）就退回不带描边的
  └ 参数推不出来的（折射、透明）用预设本身携带的信息
```

导出界面上会显示这次会绑定哪个变体，例如
「子着色器 → Hidden/lilToonOutline（Opaque + 描边）」。

### 四、查看器本身的变化

相对上一版的看板挂件，形态上换了一整套界面：

- **浮动窗口**：各面板做成可拖拽、可最小化、可停靠的浮窗。

- **部件面板**：隐藏可选部件与道具（含按骨骼缩放隐藏道具），支持锁定与隔离查看。
- **场景辅助显示**：网格地面、坐标轴等，默认全关，主页面显式打开。
- **相机**：顶视图、底视图、轴视图、默认正面视图，720° 无极旋转。

- **FBX 支持**：上一版只吃 glTF；这一版支持 FBX，并处理 FBX 里常见的绝对路径贴图
  （按文件名匹配、给 `textureBase` / `textureMap` 兜底）。
- **配置化**：整套参数走 JSON（`assets/sample.json` 是基线），支持 URL 参数传入、
  自动加载同名配置、以及导出当前配置。
- **嵌入方式**：自包含单文件版（不需要 importmap），用 `data-ba3d-*` 属性传参，
  也可以直接调 JS API。
- **嘴部修复**：沿用上一版的方案（拆 UV 岛 + 嘴部图集 + `bone_mouth` 驱动），
  现在材质跟随渲染模式。

工程侧也跟着变：

- 由 `src/` 分模块 + `dist/` 挂件，改为 `viewer.js` + `index.html` + `assets/`，
  另出一份自包含单文件版。
- 增加了**生成器与检查器**：lilToon 属性表、字段映射表、预设、着色器表都由脚本
  从 lilToon 源码生成，带 `--check` 模式；另有若干一致性检查器与固定的部署清单。

### 五、修复的问题

- **剔除方向反了**：Unity 的 `Cull Back` 意思是「剔除背面」（只画正面），
  之前理解成了「只画背面」，导致套上预设后模型里外翻转、看起来发白。
- **裁剪阈值被误用**：`_Cutoff` 只在 Cutout 模式生效，之前写成了「只要配置里有
  cutoff 就套用」，而 `_Cutoff` 的默认值本来就是 0.5，于是材质原有的 alphaTest
  被强行改成 0.5，半透明像素被裁掉，表现为材质变透明。现在只有明确是 Cutout
  模式才使用它。
- **阴影总开关没接**：`_UseShadow` 之前完全没有映射，19 个官方预设里有 5 个
  （皮肤·平涂、皮肤·描边、金属 MatCap、玻璃、轻玻璃）明确关掉了阴影，
  这些「关阴影」的意图收不到，套完预设阴影还在。
- **派生开关的自洽**：`_UseRim` / `_UseMatCap` / `_UseOutline` 这类由子参数推导的
  开关，导出自检时不再产生假的「未识别字段」；配置与预设之间来回写也不再互相覆盖。

### 六、已知限制

- lilToon 的 517 个属性里我们映射了 228 个，其余当中还有一批**会直接影响外观、
  但尚未实现**的字段，阴影分档、发光、反射、MatCap、边缘光、背光、溶解等分组里
  都有。这些字段目前既不影响预览，也不会被导出。完整缺口清单见 `LILTOON2.x.md`
  与 `CONFIG.md` 的「未完成」一节。

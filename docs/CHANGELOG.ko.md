### 3.0.1.1 lilToon 스타일 백엔드의 밝기 의미 정렬 (2026-10-10)

이번 버전은 셰이딩만 손대고 UI 와 설정 형식은 바꾸지 않았습니다: 「lilToon 스타일」백엔드의 **조명 합성**,
**출력 처리**, **기본색 출처**를 대조 백엔드(lilToon 소스)의 실제 의미에 맞춰, 눈에 보이는 밝기 편차 두 곳을 고쳤습니다.

#### 고친 문제

| 증상 | 원인 | 처리 |
|---|---|---|
| 기본 모델이 **순수 기본 설정**에서 **밝고 하얗게** 보임 | 스타일 측은 「광원별 합산」으로 직접광을 자체 계산했지만, 대조 측은 **첫 방향광**만 쓰고 광색을 **채널별로 `_LightMinLimit` / `_LightMaxLimit` 로 클램프** | 스타일 측도 **1 회 합성**으로 변경: `A × clamp(메인 + 환경, 하한, 상한) × R`, 대조 측과 같은 의미 |
| 「피부 · 애니메이션」프리셋 적용 시 스타일 측이 **오히려 어두움** | 기본색 출처가 비대칭: 스타일 측은 머티리얼 기본색을 **한 번 더 곱했고**, 대조 측은 머티리얼 자체의 유효색을 사용 | 기본색을 「유효 설정 → 설정 매핑 → vendor 실행 기본값」에서 유도해, 같은 메인 텍스처·같은 메인 레이어 세트로 합성 |
| 수광부 대면적이 **거의 순백** | 출력 단계의 톤 매핑(`LinearToneMapping`, 노출 1.15)이 대조 측에는 **없음** ⇒ 그 차이가 클리핑으로 압축됨 | 페이지 톤 매핑은 유지. 직접광을 위의 단일 합성으로 바꾸자 대면적 클리핑이 사라짐 |

#### 결과 (반영 후 실측, 검정 배경 α 합성, 밝기 `L = .2126R + .7152G + .0722B`)

| 상태 | 전체 평균 절대차 | 밝기차 > 12 비율 | 핵심 영역 (평균 절대차) |
|---|---|---|---|
| 홈 기본 모델, 순수 기본 | 0.029 | 0.076 % | 머리 +0.10 / 얼굴 +0.37 / 겉옷 +0.11 / 양말 +0.01 |
| 홈 기본 모델, 「피부 · 애니메이션」전역 | 0.000074 | 0.00016 % | 각 영역 약 0 |
| Melano (기준 포즈) | 0.050 | 0.122 % | 얼굴 −0.14 / 겉옷 −0.16 |
| Melano, 「피부 · 애니메이션」전역 | 0.00067 | 0.0029 % | 각 영역 약 0 |

- 이미 검수된 **얼굴 그림자 보정**(그림자 노멀 무조건 대입, 층별 단계에 안티에일리어싱, 경계 전환 구간)은 **그대로 유지**.
- 「lilToon 스타일」에 처음 진입할 때 뷰어가 **lilToon 브리지 모듈을 한 번 함께 로드**합니다(모듈 적재만 하고
  렌더 백엔드는 전환하지 않음). 설정 매핑과 vendor 실행 기본값을 얻기 위해서입니다.

#### 이번 버전에서 아직 검증하지 않은 것 (정직한 기록)

- `_ShadowNormalStrength` 의 **중간 강도**: 슬라이더는 기록되지만 대응 셰이더 분기는 아직 적용되지 않음.
- 메인 컬러 2/3 층(`_UseMain2ndTex` / `_UseMain3rdTex`)의 사용 분기는 별도 검증하지 않음.
- 얼굴 그림자는 **밝기** 기준만 확인했고 **모양 / 전환**의 독립 검증은 하지 않음.
- 투명 배경 분기, 다른 모델, 「지정 머티리얼」프리셋 대상은 미검증.

### 3.0.1.2 업스트림 런타임 업그레이드 three-liltoon 0.1.4 → 0.1.9 (2026-10-18)

「lilToon 소스」백엔드가 쓰는 업스트림 런타임을 **0.1.4** 에서 **0.1.9** 로 올렸습니다(vendor 와 목록만 교체, 우리 셰이딩 경로는 그대로).

#### 업스트림이 가져온 변화 (우리 쪽에서 보이는 것)

| 항목 | 0.1.4 | 0.1.9 |
|---|---|---|
| 외곽선 | 공개된 `shaderVariant` 가 없어 업스트림 외곽선을 **그릴 수 없음** ✗ | `shaderVariant: 'Hidden/lilToonOutline'` 로 그림 ✓ (실측: 스킨 메시 가는 선 정상 ✓) |
| 출력 정책 | — | 0.1.6 부터 three 의 톤 매핑 / `outputColorSpace` 추종 ✓ (우리는 `LinearToneMapping` + 노출 1.15 ✓ 실측 **밝기 이동 없음** ✓) |
| 렌더 비용 | — | 0.1.9 에서 중복 머티리얼 준비, 불필요한 framebuffer 복사·해석 감소 ✓ |
| 텍스처 방향 | — | 문서에 명시: 머티리얼自带 텍스처 뷰는 일律 `flipY = false` ✓ (업스트림 Issue 3) |

#### 우리의 처리

- **외곽선은 여전히 전부 자체 구현** ✓ (혼합 외곽선 스위치 `HYBRID_UPSTREAM_OUTLINE = false`, `viewer.js` 참고).
- 이유: BA 캐릭터에는 **모델自带 외곽선 껍질 메시**(이름에 `_Outline`, 예: `CH0155_Milk_Outline`)가 있어 업스트림 외곽선을 겹치면 큰 덩어리로 부풀어 오름 ✗. 그것을 제외하면 BA 쪽은 정상 확인 ✓ 이지만, VRC 쪽은 이 리포지터리의 테스트 모델에서 렌더 이상(텍스처 404, 이번 업그레이드와 무관) ⇒ **VRC 쪽 검증 후 켭니다**.
- vendor 파일: `index.js` · `chunk-KNGRDLOZ.js` · `chunk-WFYRXLGW.js` · `gltf.js` · `vrm.js` · `schema/…` · 서드파티 고지(옛 이름 `chunk-A4BIABDA.js` / `chunk-F6TSGO5L.js` 는 제거).
- 배포 목록, 5개 언어 `DEPLOY` 문서의 chunk 표, 5개 언어 `README` 의 버전 번호와 외곽선 설명을 동기화 ✓.

### 3.0.1.3 Unity 와의 표현 정렬(소스 백엔드) + 업스트림 네이티브 기능 대체 (2026-10-18)

이번 버전은 「lilToon 소스」백엔드의 **표현**을 Unity 에 다시 정렬하고, 소스 백엔드에서 자체 구현했던 몇 곳을 업스트림 0.1.9 의 네이티브 기능으로 바꿨습니다.

#### 고친 문제: 소스 백엔드가 밝아지고 단계가 평평해짐

| 증상 | 원인 | 처리 |
|---|---|---|
| 0.1.9 로 올린 뒤 「lilToon 소스」가 전반적으로 밝고 그림자가 평평해짐 | 업스트림 0.1.6+ 가 **renderer.toneMapping 을 따르게** 되었고, 이 페이지의 toon 모드는 **ACES**; Unity 의 lilToon 머티리얼은 tone mapping 을 **하지 않음**(ACES 는 후처리 Volume 에서만 가능) | 소스 백엔드 머티리얼 `toneMapped = false` (= 0.1.4 동작 = Unity 의미); **sRGB 출력은 유지**(Unity 는 Linear ⇒ 표시 단계에서 sRGB 변환이 원래 필요) |

실측(정지 장면, 참조 상태 = 0.1.4 빌드): 수정 전 순차 **+0.93 / +0.28 / +0.33**(밝음) → 수정 후 **−0.29 / −0.94 / −1.01**; 평균 절대차 **2.20 → 1.34**; >12 비율 **7.7% → 3.8%**.

#### 업스트림 네이티브 기능으로 교체

- **외곽선(혼합)**: 스킨 메시는 `shaderVariant = Hidden/lilToon*Outline` 로 업스트림이 그리고, 정적 메시는 자체 역확장을 계속 사용; 업스트림에 맡긴 메시는 껍질을 추가하지 않음(이중 외곽선 방지).
  ⚠️ **모델自带 `*_Outline` 껍질 메시는 반드시 제외**(그렇지 않으면 큰 덩어리로 부풀어 오름, 실측); 스위치 `HYBRID_UPSTREAM_OUTLINE`.
- **텍스처**: 생성자 파라미터 `textures` 사용(네이티브 의미; 색 공간은 업스트림 `LILTOON_TEXTURE_SEMANTICS` 가 결정).
- **렌더 큐**: `enableLilToon(renderer, { materialRenderQueue: true })` (Unity 의 정렬 의미에 더 가까움; 실측 화면 영향 없음).

#### 속성 표 자체 점검

우리의 lilToon 속성명 **199 개**가 업스트림의 **591 개** 네이티브 이름 안에서 **전부** 발견됩니다(자작/별칭 = 0).

#### 채택하지 않음 (실측 후 롤백)

프레임 단위 후처리(tone mapping 을 머티리얼에서 프레임 pass 로 이동, Unity Volume 의미): 업스트림 `enableLilToon` 의 렌더 래핑과 충돌(render target 을 다시 쓰고 framebuffer 캡처를 수행) ⇒ 우리 RT 가 비어 버림 ⇒ **롤백**, 머티리얼 단위 방식을 유지.

#### 알려진 잔여 사항

- VRC(FBX) 쪽 업스트림 외곽선 표현은 미검증(이 리포지터리의 테스트 모델이 전부 검게 나옴; 0.1.4 도 동일하게 검음 ⇒ fixture 문제).
- 업스트림에는 아직 매핑하지 않은 속성이 392 개 있음(모발 / 굴절 / 보석 / 큐브 반사 등).

## 3.0.0

> **기능 소개(GitHub Release 3.0.0 과 정렬)**: 이 버전은 「lilToon 소스 판 도입 + FBX 경험 개선」한 메이저 버전입니다.

1. three.js 를 **r0.185.1** 로 업그레이드;
2. 여러 문제 수정;
3. 렌더에서 **Toon** 을 고를 때 셰이더 옵션에 **lilToon 소스** 추가(three-liltoon 도입: 업스트림 lilToon 셰이더 코드를 직접 번역);
4. FBX 모델 가져오기 시 프리팹을 골라 파츠 표시·숨김을 정확히 처리;
5. FBX 모델 보기 경험 개선, **anim 애니메이션 재생(실험적)** 구현;
6. VRC 아바타 Unity 프로젝트의 `assets` 폴더 전체를 바로 가져오기(내부의 FBX, 프리팹, 텍스처, 셰이더 설정, 씬, anim 자동 인식);
7. 사이트 favicon 과 두 페이지의 `<link rel="icon">`(이번 **3.0.1** 에서 도입, 해당 절 참고).

> 아래 본문은 같은 버전의 기술 세부 기록입니다. 위 기능 소개와 충돌하지 않습니다: 기능 목록은 릴리스 노트용, 본문은 구현 추적용입니다.

이전 버전(`legacy-v1`)은 **드래그 가능한 3D 캐릭터 위젯**으로, 어떤 사이트에든 임베드되는 드래그 위젯이며 셰이딩은 게임 느낌의 툰 단계뿐이었습니다.

이번 버전은 그것을 **캐릭터 3D 뷰어**로 만들었고, 주된 목표는 **lilToon 스타일 셰이딩을 추가하고 뷰어의 lilToon 설정이 Unity 원본과 상호 호환되게** 하는 것이었습니다.

### 一. lilToon 스타일 셰이더 추가

「셰이더」드롭다운이 기존 2 단계에서 3 단계로 늘었습니다:

| 옵션 | 설명 |
|---|---|
| 주입 안 함(기본) | 모델自带 머티리얼을 그대로 사용, 아무 변형 없음 |
| Cel 밴딩 | 이전 버전에도 있던 게임 느낌 툰 셰이딩 |
| **lilToon 스타일** | 이번에 추가, lilToon 2.3.4 소스를 참조해 구현 |

구현 방식은 **lilToon 2.3.4 소스**를 항목별로 정렬한 것이지, 느낌을 보며 값을 맞춘 것이 아닙니다:

- `Shader/lts.shader` 의 Properties 구간에서 **속성 517 개**를 기준 표로 추출(스크립트 생성, 재현 가능) 후 뷰어가 이미 구현한 필드와逐一 대응, 현재 **228 개** 정렬.
- 매핑 시 **형태 검증**: 색-색, 벡터-벡터, 텍스처-텍스처, 정수-정수, 형태가 다른 것은 억지로 넣지 않음. 검증한 80 항목은 전부 통과.
- 파라미터 패널은 lilToon 관례대로 그룹화하고 접을 수 있음: 그림자 단계, 외곽선, Stencil 모델, Stencil 외곽선, MatCap, MatCap 2nd, 발광, 발광 2nd, 디더 Dither, 노멀, 메인 컬러 2nd, 메인 컬러 3rd, 디졸브.

구현된 기능:

- **3 층 그림자 단계**: `_ShadowStrength` / `_ShadowBorder` / `_ShadowBlur`, 그리고 2·3 층의 단계 색과 경계, `_ShadowBorderRange` 의 전환 구간.
- **실시간 그림자 수신**: 층마다 투영 수신 여부를 따로 결정(`_ShadowReceive` 등), 수식은 lilToon 과 동일(`lerp(1.0, shadow, _ShadowReceive)`).
- **그림자 전체 스위치**: `_UseShadow`, 끄면 그림자 계산 구간 전체가 생성되지 않음.
- **외곽선**: 역확장 외곽선, 폭 마스크·확장 방향 텍스처·외곽선 수광·`fixWidthMode`·`skipPattern` 등 lilToon 의 외곽선 속성 포함.
- **메인 컬러 레이어**: 메인 텍스처의 UV 변환·스크롤, HSV 보정, 2·3 층의 데칼과 블렌드 모드.
- **림라이트 / MatCap / 역광 / 반사 / 발광**: lilToon 의 수식과 순서로 연결.
- **렌더 상태**: `_TransparentMode`, `_Cutoff`, `_Cull` 을 실제 렌더에 동기화.

### 二. lilToon `.asset` 프리셋 양방향 호환

목표는 **뷰어 설정과 Unity 의 lilToon 실제 산출 파일이 서로 읽고 쓸 수 있게** 하는 것이며, 양방향 모두 구현했습니다:

- **가져오기**: `.asset`(Unity 의 lilToon 프리셋), `.mat`(머티리얼), `.json` 인식, 끌어다 놓으면 형식을 자동 판별.
- **내보내기**: Unity 가 바로 불러올 수 있는 lilToon 프리셋 텍스트 생성, 필드 이름은 lilToon 원래 이름(`_UseOutline` 등), 값은 float32 로 기록.

부수细节:

- **공식 프리셋 19 개 내장**, lilToon 自带 `Presets/*.asset` 에서 직접 생성(손으로 옮긴 것 아님). 분류(피부, 머리, 옷감, 자연, 무기물, 효과, 기타)는 Unity 측과 동일.
- **머티리얼별 설정**: 패널 상단에 머티리얼 드롭다운이 있어 특정 머티리얼에만 프리셋을 적용하거나 파라미터를 바꿀 수 있고, 나머지는 전역 기본값을 유지. 수정한 머티리얼은 드롭다운에 표시가 붙고, 덮어쓰기를 한 번에 지울 수도 있음.
- **내보내기 진입점은 lilToon 파라미터 패널 안**, Unity 관례와 동일(프리셋 가져오기/내보내기가 모두 lilToon 자체 메뉴에 있음). 내보낼 때 선택 가능:

  - **종류**: 기본 「자동」, 머티리얼 이름으로 추정(hair→머리, skin→피부, cloth→옷감, 나머지→기타); 일곱 항목 중 하나를 직접 지정할 수도 있음.
  - **셰이더**: 기본 「자동」, 현재 파라미터로 유도; 구체 배리언트를 직접 지정할 수도 있음.
  - **현재 머티리얼 내보내기**: 머티리얼 하나당 `.asset` 하나, 파일명은 `모델명_머티리얼명.asset`.
  - **모든 머티리얼 내보내기**: 머티리얼마다 파일 하나씩.

### 三. 서브 셰이더(배리언트) 처리

이번 호환 작업의 핵심 발견이라 따로 설명합니다.

**Unity 의 lilToon 「메인 셰이더」는 모든 기능을 담고 있지 않습니다.**
메인 셰이더 `lilToon`(`lts.shader`)에는 pass 가 4 개만 붙어 있고
(`FORWARD`, `FORWARD_ADD`, `SHADOW_CASTER`, `META`), **외곽선 pass 가 없습니다**.
그래서 머티리얼이 메인 셰이더를 쓸 때는 `_UseOutline = 1` 이어도 외곽선이 렌더되지 않으며,
`Hidden/lilToonOutline` 으로 바꿔야 합니다(`FORWARD_OUTLINE` 등 pass 가 추가됨).

그리고 lilToon 에는 셰이더가 **64 개** 있는데, 그중 **머티리얼 패널에서 고를 수 있는 이름은 1 개**뿐이고
나머지 63 개는 `Hidden/*` 또는 `_lil/*` 배리언트(유리 굴절, 투명, 모발, 보석 등)라
**프리셋으로만 바인딩**할 수 있습니다.

그래서 뷰어가 프리셋을 내보낼 때 올바른 서브 셰이더를 자동으로 유도해 기록합니다:

```
_TransparentMode 로 기본 모드 결정
  ├ 외곽선이 켜져 있으면 대응하는 *Outline 배리언트로
  ├ 그 모드에 외곽선 배리언트가 없으면(굴절 / 모발 / 보석) 외곽선 없는 것으로
  └ 파라미터로 유도할 수 없으면(굴절, 투명) 프리셋 자체가 가진 정보 사용
```

내보내기 화면에는 이번에 어떤 배리언트를 바인딩하는지 표시됩니다, 예:
「서브 셰이더 → Hidden/lilToonOutline (Opaque + 외곽선)」.

### 四. 뷰어 자체의 변화

이전 버전의 위젯에 비해 인터페이스를 전면 교체했습니다:

- **플로팅 창**: 각 패널이 드래그·최소화·도킹 가능한 독립 창.
- **패널**: 셰이딩과 외곽선, lilToon 파라미터, 파츠, 씬, 내보내기.
- **라이팅 프리셋**: 낮, 아침 / 저녁, 밤, 그 외 메인 라이트 방위각·고도·강도·색과 환경 천지색 미세 조정.
- **렌더 모드**: 원본 PBR, 툰 Cel; 외곽선은 켜기/끄기와 두께 조정.
- **파츠 패널**: 선택 파츠와 소품 숨김(본 스케일로 소품 숨김 포함), 잠금과 격리 보기 지원.
- **씬 보조 표시**: 그리드 바닥, 좌표축 등, 기본은 전부 꺼짐, 메인 페이지에서 명시적으로 켬.
- **카메라**: 상단 뷰, 하단 뷰, 축 뷰, 기본 정면 뷰, 720° 무단 회전.
- **모델 위치 보정**: 회전 기준과 모델 오프셋을 설정 가능, 「캐릭터가 화면을 벗어남」 해결.
- **FBX 지원**: 이전 버전은 glTF 만 지원; 이번 버전은 FBX 를 지원하고 FBX 의 흔한 절대 경로 텍스처를 처리(파일명 매칭, `textureBase` / `textureMap` 폴백).
- **설정화**: 모든 파라미터가 JSON(`assets/sample.json` 이 기준), URL 파라미터 전달, 동명 설정 자동 로드, 현재 설정 내보내기 지원.
- **임베드 방식**: 자체 완결 단일 파일 판(importmap 불필요), `data-ba3d-*` 속성으로 파라미터 전달, JS API 직접 호출도 가능.
- **입가 보정**: 이전 버전 방식을 계승(UV 아일랜드 분할 + 입가 아틀라스 + `bone_mouth` 구동), 이제 머티리얼이 렌더 모드를 따름.

프로젝트 구조도 함께 바뀌었습니다:

- `src/` 모듈 + `dist/` 위젯에서 `viewer.js` + `index.html` + `assets/` 로 변경, 자체 완결 단일 파일 판도 별도 제공.
- **생성기와 검사기** 추가: lilToon 속성 표, 필드 매핑 표, 프리셋, 셰이더 표를 모두 lilToon 소스에서 스크립트로 생성하며 `--check` 모드가 있음; 그 외 일관성 검사기 몇 가지와 고정된 배포 목록.

### 五. 고친 문제

- **컬링 방향이 반대**: Unity 의 `Cull Back` 은 「뒷면 컬링」(앞면만 그림)이라는 뜻인데,
  이전에는 「뒷면만 그림」으로 이해해, 프리셋을 적용하면 모델이 뒤집혀 하얗게 보였음.
- **컷오프 임계값 오용**: `_Cutoff` 는 Cutout 모드에서만 유효한데, 이전에는 「설정에 cutoff 가 있으면 적용」으로
  구현했고 `_Cutoff` 기본값이 원래 0.5 라서, 머티리얼의 기존 alphaTest 가 0.5 로 강제 변경되어
  반투명 픽셀이 잘려 머티리얼이 투명해 보였음. 이제 Cutout 모드일 때만 사용.
- **그림자 전체 스위치 미연결**: `_UseShadow` 가 전혀 매핑되지 않아, 공식 프리셋 19 개 중 5 개
  (피부·플랫, 피부·외곽선, 금속 MatCap, 유리, 가벼운 유리)가 명시적으로 그림자를 껐는데도
  그 의도가 전달되지 않아 프리셋 적용 후에도 그림자가 남았음.
- **파생 스위치의 자기 정합성**: `_UseRim` / `_UseMatCap` / `_UseOutline` 처럼 하위 파라미터에서 유도되는
  스위치가 내보내기 자체 점검에서 가짜 「미인식 필드」를 만들지 않게 했고, 설정과 프리셋 사이를 오가는 쓰기도 서로 덮어쓰지 않게 함.

### 六. 알려진 제한

- lilToon 517 속성 중 228 개를 매핑했고, 나머지에는 **외형에 직접 영향을 주지만 아직 구현하지 않은**
  필드가 있습니다 — 그림자 단계, 발광, 반사, MatCap, 림라이트, 역광, 디졸브 등의 그룹에 있습니다.
  이 필드들은 현재 미리보기에도 영향을 주지 않고 내보내지도 않습니다. 전체 목록은 `LILTOON2.x.md` 와
  `CONFIG.md` 의 「미완성」절을 참고하세요.
- **`.mat` 머티리얼 파일 내보내기는 아직 없습니다**(가져오기만 지원). Unity 머티리얼을 가져올 수는 있지만
  반대로 `.mat` 을 생성하는 것은 아직 비어 있습니다.
- 굴절, 모발, 보석 세 모드는 웹 쪽에 대응 셰이더 구현이 없어 미리보기 시 투명으로 처리하고
  안내를 표시하며, 내보낼 때는 올바른 서브 셰이더를 기록합니다.
- 여러 인스턴스는 각자 렌더러와 GPU 리소스를 보유합니다(이전 버전의 제한 계승).
  캐릭터를 여러 개 원하면 인스턴스 하나로 전환하는 편을 권합니다.
